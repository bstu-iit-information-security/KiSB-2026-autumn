## Постановка задачи

Разработать единое консольное приложение для:

1. **Кода Хемминга (ч.1).** Текст из файла `message.txt` (русские и английские буквы, цифры, служебные символы) переводится в двоичный вид (Windows-1251, 8 бит на символ). Для полученного слова `X_k` строится проверочная матрица Хемминга `H` с `d_min = 3` и `d_min = 4`, вычисляются `X_r`, передаётся слово с 0, 1 и 2 ошибками в случайных позициях, по `Y_r'` вычисляется синдром `S`, формируется вектор ошибки `E_n` и исправляется одиночная ошибка.
2. **Итеративных кодов (ч.2).** В таблице 5.2 всего 5 вариантов, поэтому номеру 12 по списку соответствует вариант ((12 − 1) mod 5) + 1 = **2**: `k = 20`, раскладки:

   | k1 | k2 | z | Группы паритетов |
   |----|----|---|------------------|
   | 4  | 5  | – | 2; 3 |
   | 2  | 10 | – | 2; 3 |
   | 2  | 5  | 2 | 2; 3; 4; 5 |
   | 2  | 2  | 5 | 2; 3; 4; 5 |

   Для каждой раскладки слово `X_k` вписывается в матрицу, вычисляются паритеты, формируется `X_n`, вносятся случайные ошибки кратности `i`, ошибки находятся и исправляются (`Y_n'`). Корректирующая способность оценивается отношениями `N2/N1` (кратность определена верно) и `N3/N1` (все ошибки исправлены).

## Теоретические положения

Число проверочных битов кода Хемминга — минимальное `r`, при котором `2^r ≥ k + r + 1`. Матрица `H = [P' | I]`: столбцы `P'` — `r`-битные числа веса 2, затем 3 и т. д. в порядке возрастания (листинг 4.2), `I` — единичная матрица `r × r`. Для учебного примера `k = 4` программа получает ту же `H(7,4)`, что и в методичке. Для `d_min = 4` к `H` добавляется строка из единиц (4.8). Чтобы `H` осталась канонической, эта строка заменяется суммой всех строк. Тогда синдром нечётного веса означает одиночную ошибку, а ненулевой синдром чётного веса — двойную, которая обнаруживается, но не исправляется.

Итеративный код раскладывает `X_k` по таблицам `k1 × k2` (в 3D — `z` плоскостей). Группы паритетов в порядке рис. 5.4: H — строки, V — столбцы, D — диагонали, A — антидиагонали, Z — паритеты по оси Z. Количество групп `g` означает первые `g` групп этого списка. В 2D диагонали обычные (`k1 + k2 − 1` проверок, рис. 5.3). В 3D используются объединённые циклические диагонали, `max(k1, k2)` на плоскость (рис. 5.4). `X_hv` — паритет всего слова. Пример рис. 5.1 (`011101111 → 0010011`) проверяется программой при запуске.

## Реализация

`main.cpp` не использует динамические контейнеры и выделение памяти в куче: все буферы фиксированного размера. Сообщение может содержать до 256 символов (`k ≤ 2048`, `r ≤ 13`), поэтому программа не привязана к длине сообщения. Столбец `H` хранится как 16-битное число. `X_r` вычисляется как XOR столбцов `P'` по единичным битам `X_k` через битовую маску, без ветвлений. Поиск столбца, равного синдрому, и инверсия ошибочного бита тоже выполняются без зависящих от данных переходов.

Декодер итеративного кода — итеративное инвертирование битов. Информационный бит инвертируется, пока ошибочными остаются больше половины его групп паритетов. Оставшиеся ошибочные проверки относятся к ошибкам в самих проверочных битах. Если чётность числа найденных ошибок противоречит `X_hv`, слово помечается как «обнаружено, но не исправлено». Случайные позиции ошибок задаёт SplitMix64 с фиксированным `seed`, поэтому запуски воспроизводимы.

## Сборка и запуск

### Visual Studio 2022 (рекомендуется)

Откройте `Lab2Variant12.sln`, затем нажмите `Ctrl+F5`. Рабочая папка — каталог проекта, поэтому `message.txt` подхватывается автоматически. Исходник компилируется с `/utf-8`, консоль переключается в UTF-8, и кириллица выводится корректно.

### Через командную строку

```powershell
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic main.cpp -o kisb_lab2_variant12.exe
.\kisb_lab2_variant12.exe message.txt 12 11001010111010001101
```

Аргументы (все необязательные): файл сообщения (по умолчанию `message.txt`), `seed` генератора ошибок (по умолчанию 12) и `X_k` для ч.2 — строка из 20 нулей и единиц (по умолчанию первые 20 бит сообщения). Также приложен `CMakeLists.txt`, он копирует `message.txt` в каталог сборки.

## Результаты

Весь вывод дублируется в файл `lab2_output.txt`. В нём есть исходное сообщение, `k`, `r`, `n`, матрица `H`, слова `X_k`, `X_r`, `X_n`, `Y_n`, `Y_r`, `Y_r'`, синдром `S`, вектор ошибки `E_n` и результат декодирования для 0, 1 и 2 ошибок. Это сделано для обоих `d_min`. Дальше идут таблицы итеративного кода, разбор 1–3 случайных ошибок для каждой раскладки и таблица `N2/N1`, `N3/N1` по 10 000 слов на ячейку для `i = 1…4`, с `X_hv` и без него. Контрольный вывод приложен в `sample_output.txt`.

Ожидаемые выводы:

- `d_min = 3`: одиночные ошибки исправляются всегда, двойные всегда обнаруживаются (`S ≠ 0`), но в 72% случаев исправляются ложно.
- `d_min = 4`: все двойные ошибки обнаруживаются и не исправляются.
- Итеративные коды исправляют все одиночные ошибки. С ростом числа групп паритетов исправляется всё больше многократных ошибок, но падает скорость кода: при 5 группах и `i = 4` исправляется 97–98% слов при `k/n ≈ 0,31`.
