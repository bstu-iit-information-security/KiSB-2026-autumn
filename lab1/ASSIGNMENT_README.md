# ЛР №1 — Вариант 1

Этап 1: комбинирование алгоритмов генерации методом Макларена–Марсальи (N=10, K=5).
Этап 2: генерация большого простого числа с тестом Соловея–Штрассена.

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate   # опционально
pip install -r requirements.txt
```

## Структура

```
lab1/
├── src/
│   ├── rng/
│   │   ├── lcg.py        # общий ЛКГ (§4.1), проверка условия макс. периода
│   │   ├── mm_combine.py # комбинатор Макларена-Марсальи (§4.8)
│   │   ├── factory.py    # build_variant1_generator() - точно по варианту 1
│   │   └── seeding.py    # генератор Этапа 1 как сид для Этапа 2 (см. ниже)

```

## Запуск

Из директории `lab1/`:

```bash
# Этап 1
python3 -m src.main sequence --length 20      # вывести последовательность
python3 -m src.main stats --length 2000       # частоты + хи-квадрат
python3 -m src.main period                    # период комбинированного генератора

# Этап 2
python3 -m src.main prime --bits 64 --rounds 8            # практическая схема
python3 -m src.main prime --bits 12 --rounds 5 --naive    # буквальная схема (Этап 1 напрямую)

# Тесты
python3 -m pytest -v

# Данные и графики для отчёта
python3 report/generate_report.py
```

## Важное замечание для отчёта: почему у Этапа 2 два режима

Генератор варианта 1 (N=10, K=5) **удовлетворяет** достаточному условию
максимального периода (§4.1, свойство 4) — период G1 равен 10, G2 равен 5,
максимум для своих алфавитов. Но для N с несколькими простыми делителями это
условие вырождается в `a ≡ 1 (mod N)`, то есть генератор становится чисто
аддитивным (генератором Вейля) — простой и предсказуемой арифметической
прогрессией.

Из-за этого:

1. **Максимальный период здесь ≠ достаточный период.** T=10 отлично
   подходит для статистического исследования Этапа 1, но на много порядков
   меньше, чем 2^p различных p-битных чисел, нужных для генерации простых на
   Этапе 2 уже при p≈16-20 бит. `naive_candidate_factory` реализует
   "буквальную" схему прямо на этом генераторе — специально, чтобы показать
   эту нехватку на практике (см. `tests/test_candidate.py::
   test_variant1_generator_too_short_for_large_candidates`, а также
   раздел "naive_vs_practical" в `report/generate_report.py`, где видно,
   что даже успех при небольших p (12, 16 бит) — по сути везение: среди
   считанных достижимых кандидатов случайно нашлось простое число).

2. Методичка ЛР №6 прямо разрешает интегрировать в Этап 2 "*базовые
   механизмы генерации*" Этапа 1, а не буквально его числовой поток. Поэтому
   для практических размеров (`seeded_candidate_factory` в `src/rng/
   seeding.py`) генератор Этапа 1 используется как источник **сида** для
   `random.Random` — то есть Этап 1 по-прежнему определяет всё "случайное"
   зерно вычисления, но дальнейшие биты берутся из качественного
   генератора, а не из 10-значного цикла напрямую.

Это разумно включить в отчёт как отдельный пункт: сначала показать, что
условие максимального периода выполнено и проверено тестами, затем показать
эмпирически, что "максимальный" не значит "достаточный", и объяснить выбор
архитектуры Этапа 2.
