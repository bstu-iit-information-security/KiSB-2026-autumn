# Лабораторная работа 4

Ярома А. И. Вариант 12. C++17, аффинная кривая bign-curve256v1, обмен ECDH, подпись СТБ 34.101.45 и выбор одноразового ключа k за фиксированные 100 попыток.

## Запуск в Visual Studio

Откройте `Lab4Variant12.sln`, выберите **Release | x64**, нажмите **Ctrl+F5**. Требуется рабочая нагрузка «Разработка классических приложений на C++» и Windows SDK. Решение использует установленный по умолчанию набор инструментов.

Программа генерирует две эфемерные пары ключей, выводит открытые координаты и общий секрет, подписывает три сообщения и проверяет отказ после изменения байта подписи. Затем показывает одинаковое число операций при выборе первого и последнего допустимого k. При каждом запуске публичные ключи, общий секрет и подписи меняются.

В `sample_output.txt` сохранён результат проверенного запуска. Сообщения и контрольные хэши взяты из опубликованных проверочных примеров СТБ.

## Ввод

Без аргументов запускаются три заданных в коде сообщения. Один необязательный аргумент задаёт сообщение в Hex, максимум 256 байт. Пример из Developer PowerShell после сборки решения:

```powershell
.\x64\Release\Lab4Variant12.exe 001122aabb
```

Числовые параметры и координаты выводятся в big-endian Hex. Сообщения, хэши и подписи выводятся как последовательности байтов в исходном порядке. Стандарт BIGN интерпретирует скаляры из своих байтовых строк как little-endian. Форматы PEM, DER, ASN.1 и X.509 программа не разбирает.

## Архитектура

1. `arithmetic.hpp/.cpp` и `curve.hpp/.cpp` образуют математическое ядро. Число состоит из восьми 32-битных слов. Модуль реализует арифметику по модулю p и q, аффинные точки, сложение, удвоение и контрольное Double-and-Add для публичных скаляров.
2. `protocols.hpp/.cpp` реализуют ECDH и BIGN. Вспомогательный БелТ в `belt.hpp/.cpp` переиспользован из третьей лабораторной, belt-hash построен по стандарту. Протоколы используют математическое ядро и вызывают защищённое умножение из модуля 3.
3. `secure.hpp/.cpp` реализуют выбор первого допустимого k масками из пакета 100 кандидатов, источник случайности ОС и лестницу с 256 одинаковыми шагами. Криптографические рабочие массивы имеют фиксированный размер.

Вход программы находится в `main.cpp`, проверки — в `tests.cpp`. Секретные скаляры обрабатывает `multiply_secret`. Функция `multiply_public` используется при проверке открытых ключей и подписей.

## Расхождение формул в методичке

В условии под заголовком «СТБ 34.101.45 / ГОСТ Р 34.10-2012» приведена схема с r = x(kG) mod q и s = rd + ke mod q. Реальный СТБ 34.101.45 задаёт BIGN с компонентами S0 и S1 и другим уравнением проверки.

Основная подпись программы — стандартный BIGN с belt-hash. В тестах воспроизводится опубликованный пример подписи. Отдельные функции `course_sign` и `course_verify` реализуют уравнения пары (r,s) из методички. Их демонстрация явно подписана как учебная схема GOST-style.

## Проверки

Из Developer PowerShell for VS в каталоге исходников:

```powershell
cmake -S . -B build -G "NMake Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
```

Проверяются арифметика переносов и заимствований, инверсия, точка на бесконечности, порядок G, опубликованный открытый ключ, три хэша и стандартная подпись, совпадение ECDH, отказ при искажении подписи и сообщения, неверные диапазоны и ошибки источника случайности. При ошибке входа программа возвращает ненулевой код.

## Границы анализа безопасности

Пакет состоит из 3200 случайных байтов. В Windows он заполняется через BCryptGenRandom. Цикл всегда проверяет 100 кандидатов, выбирая первый из диапазона 1..q-1 без ветвления по найденному кандидату. Если допустимых кандидатов нет, возвращается явная ошибка. Повторной генерации или замены остатком по модулю нет. При равномерных независимых кандидатах выбор равномерен среди 1..q-1.

Аффинное сложение выбирает частные случаи масками. Инверсия имеет фиксированную последовательность шагов по малой теореме Ферма, а защищённое умножение выполняет по одному сложению и удвоению на каждый из 256 битов. Это анализ структуры исходного кода. Устойчивость к физическим атакам и всем особенностям компилятора и процессора требует отдельного исследования.
